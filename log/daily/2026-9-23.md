## Device Mapper

### 1. 工程 P0：`DM_READONLY_FLAG` 的 table 级语义

- 依据 Linux DM UAPI 与 Linux 6.6 Device Mapper 实现核对：readonly 是加载 table 的 mode；inactive table 不改变当前 active I/O mode，成功 resume 激活/替换 table 后才切换只读状态。
- 将 readonly 从 `DmDevice` 的永久 `AtomicBool` 移至不可变 `DmTable`：`DM_TABLE_LOAD` 解析 flag 并随 inactive table 暂存；BIO 分派在同一 state 锁快照中选择 active table 与 mode；suspended 期间已接收的 write-like BIO 若在 readonly table 上 replay，则完成为 I/O error 并释放 in-flight 计数。
- `DM_DEV_STATUS`、`DM_TABLE_STATUS` 与 `DM_TABLE_DEPS` 的 active/inactive 查询改为捕获选中 table 和对应 readonly 状态的同一快照；tableless `DM_DEV_CREATE` 不再持久化 readonly flag。
- 新增/更新 Rust、focused C 与 NixOS control-plane 覆盖：验证 inactive readonly、首次 resume 激活 readonly、readonly active 上加载 writable inactive、resume 后恢复可写，以及真实 `dmsetup --readonly create → reload → resume` 路径。
