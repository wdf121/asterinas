## 1. Linux 对照与第一阶段 ABI

固定 Linux `v6.18.56` 为主要语义基线，`v7.2.10` 为首次新版差异核对；两者 DM ABI 均为 4.50.0。内核版本与 DM ABI 版本是不同概念，也不承诺实现全部 Linux DM 能力。

- 每次 ioctl 经 LSM 检查 initial user namespace 的 `CAP_SYS_ADMIN`，拒绝返回 `EACCES`；节点 0600 的打开权限不能替代调用时权限检查，尤其是保留/传递 fd 或打开后降权。
- 识别 DM ioctl 类型后，独立读取并回写 12 字节版本；要求 major 相同、客户端 minor 不高于内核，patch 不参与拒绝。
- 版本 copyout 的 `EFAULT` 优先于不兼容版本的 `EINVAL`；未知 DM 命令也先完成版本协商。
- `DM_VERSION` 握手完成直接返回，不再读取或校验其余头部、flags、name 和 payload。
- 增加两项版本 ktest、312 字节头部断言及真实 ioctl C 回归；原有 C 程序补普通参数校验失败前的版本回写验证。

10-14 PR 3 档案中的“Linux major-only”与“两段全量复制对齐 Linux”结论已勘误，但未修改 PR 分支。普通命令头部快照、逐命令布局约束、实际输出长度、失败整包回写和 secure-data 清理留待第二阶段。

## 2. 自动启动变慢的定位与修复

原先完整 linear 约 186～202 秒，不能仅用测试工作量解释。FIFO/tee 自动运行没有响应 systemd/getty 的终端查询，叠加 guest Jiffies 超时异常，是本次可观察的重要原因。

新增 `myshell/lib/dm_terminal.py`：从当前日志末尾旁路观察，响应 XTGETTCAP 名称、窗口尺寸、光标查询，提供固定 xterm/24×80；未知 capability 返回否定应答。命令与应答通过单 writer 注入 child stdin；stdin EOF 后仍服务关机查询。原始 QEMU stdout/stderr 不经新增过滤器，避免非阻塞 chardev 背压。

正式接入后完整 linear 一次为 85 秒；默认容量改为 768 MiB 后独立验证为 88 秒，最终六套串行中的 linear 为 84 秒。通用 Jiffies 异常没有修复，也未重启外层 VM，不能把终端应答收益表述为内核时钟问题闭环。

## 3. 六套日志与测试意图

- 默认结构化精简模式：准备阶段一次性展示 40 秒 shell-ready 与 180 秒完整生命周期（包含 ready 阶段）、盘路径/容量；只在首轮输出 BOOT starting，每轮保留 ready 耗时、BOOT finished 和 PASS，去掉重复绝对时间。
- 最后一轮 PASS 移到详细输出之前，仍在退出状态、失败标记、对应 guest PASS 检查之后；单/双/三轮 runner 的成功和失败六条模拟路径此前均验证，失败不得发 PASS。
- 六套补齐目标与覆盖边界；其余五套仅修改 host 日志语句，没有修改 guest 测试参数或内容。
- linear 最终容量由 512 改为 768 MiB：256→第一 PV 内 288→第二 PV 新增 480、最终 768→缩回 256。初始文件 64、新增文件 240，共 304>288 MiB，保证覆盖第二 PV；缩容前删新增文件。
- striped：四盘两组，chunk 4 KiB，512→576→1024→512 MiB，文件 128+480=608>576 MiB，覆盖新增组。
- mixed：linear 256 + 双盘 striped 256 = 512 MiB，文件 64+256=320>256 MiB，重启只读检查，不缩容。
- control-plane 验证控制生命周期；dataplane 验证裸块映射与边界；topology 验证 LVM/DM 拓扑，不创建文件系统。

`-L 768M` 是最终 LV 大小，不是增加 768 MiB。底层盘各 512 MiB；默认数据区从 1 MiB 起、PE 为 4 MiB，每盘可分配 508 MiB，两盘共 1016 MiB。PV 元数据/对齐开销与文件系统元数据/保留块分属不同层，不能混算。

默认 `RESET_DM_TEST_IMAGES=1` 每套开始删除指定测试盘，runner 随后重建；同套多轮之间保留。因此再次运行显示“待创建”是预期行为。本轮未改变重置策略。
