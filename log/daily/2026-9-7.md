# 2026-9-7 Device Mapper 进度

## 历史问题：首次 resume 的发布顺序

> 此问题已于 2026-09-09 解决；实际改动与验证见 [2026-9-9.md](2026-9-9.md)。以下保留 2026-09-07 的问题背景。

当前首次 `resume` 先完成 mapper block device 注册：block registry 从 `Pending` 提交为 `Live`，创建 `/dev/dm-X` 和 `/dev/mapper/<name>`，并开始接受 `open`；随后才执行 `DmDevice::resume()`，将 `inactive` table 切换为 `active`。

这会留下一个短暂的 `Live` 但尚无 active table 的窗口。并发用户可能已打开节点并提交 I/O，随后因 `DmDevice::enqueue()` 找不到 active table而被拒绝。该窗口不会把 I/O 映射到错误后端，但可能产生瞬时、用户可见的 I/O 失败。

建议后续将首次发布重构为三阶段事务：

```text
prepare
  block registry 保持 Pending
  创建 BlockFile、/dev/dm-X 和 mapper alias
  暂不接受 open

activate
  DmDevice inactive -> active

publish
  block registry Pending -> Live
  BlockFile 开始接受 open
```

若 activate 或 publish 失败，应统一回滚 table、节点、alias、BlockFile 和 block registry，避免半发布状态。
