## 4. OSDK 0.19.0 ktest selector 语义核实与 10-13 记录勘误

### 背景

定向复验 PR 3 时以 `cargo osdk test aster_core::device::misc::device_mapper::tests` 形态运行,得 0 passed / 160 filtered 且 EXIT=0;读 OSDK 源码定位原因。

### 事实

- OSDK 将 selector 原样编进测试内核的 `KTEST_TEST_WHITELIST`;过滤为 `SuffixTrie::contains`,从测试路径末段(函数名)反向匹配,白名单条目须等于测试路径的某个后缀。
- 裸模块路径选择器(不含函数名)永远匹配空集:必然全 filtered、EXIT=0,属假绿形态之一。
- 可靠入口:不带 selector 跑 crate 全量,以串口聚合计数与逐测试行取证;逐行格式中模块名段为 `test`(如 `aster_core::device::misc::device_mapper::test::<fn>`)。

### 勘误

[2026-10-13](2026-10-13.md) 第 4 节 aster_core 集成层一行的 81/159 无法按 0.19.0 语义产生;当日 cargo-osdk 恰由 0.18.1 重建为 0.19.0,若该轮实为 0.18.1 下运行(旧语义假设)则可解释,但未验证。该行按无效取证对待,原文已加勘误注记;同表 block 28/0 与 device-mapper crate 87/0 为无 selector 运行,不受影响。

### 验证

同环境两轮对照:selector 形态 0 passed / 160 filtered;无 selector 160 passed / 0 failed / 0 filtered。
