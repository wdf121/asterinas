# 2026-9-14

## 1. Device Mapper GDB 内核路径验证

### 背景

需要把 guest 中 `dmsetup` 的 `strace` syscall 证据接到 Asterinas 内核中的实际控制面分派路径，验证 `/dev/mapper/control` 请求确实抵达 Device Mapper ioctl 实现。

### 改动

- 使用带调试符号的 NixOS 内核产物进行 QEMU 远程 GDB 调试；当前 `asterinas-osdk-bin` 已确认包含 `.debug_info`、`.debug_line` 和 `.symtab`。
- 未修改 Device Mapper 生产源码、测试脚本或启动脚本。

### 验证

- QEMU 以 GDB stub 启动后，GDB 成功设置 `DmControlFile::ioctl` 的硬件源码断点。
- guest 执行 `dmsetup version` 时，断点实际命中 [kernel/core/src/device/misc/device_mapper.rs](../kernel/core/src/device/misc/device_mapper.rs) 的 ioctl 入口。
- GDB 调用栈确认内核路径为：`syscall_dispatch → sys_ioctl(raw_fd=3) → inode_handle::ioctl → DmControlFile::ioctl`。
- 在控制面入口观察到 `raw_cmd=0xc138fd00`、解码后 `command=0`、`data_size=16384`、`data_start=312`；回写后同一用户 buffer 的 version 三项为 `4, 48, 0`。
- `dmsetup targets` 已有 strace 的 `DM_VERSION + DM_LIST_VERSIONS` 证据；其 GDB 可变长 target-version records 观察尚未完成。
