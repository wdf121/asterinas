## 1. 内核设备模型方案 A：块设备接入设备模型（sysfs 修复）

### 背景

`--linear-integration` 在 `DM_UUID_FLAG` 修复（10-10 日志第 8 节）后仍失败：upstream 设备模型创建空的 `/sys/dev/block` 目录，LVM2 的 sysfs filter 据此拒绝一切块设备。根因是块设备从未注册进设备模型，而块类设备（DM/virtblk）的 `/dev` 节点由 registry 自行发布。

### 改动

- `kernel/core/comps/device/src/common/subsystem.rs`、`class/mod.rs`、`bus/mod.rs`：引入 `CREATES_DEVNODE` 类属性与 `creates_devnode()`——自发布 `/dev` 节点的类可显式 opt-out；opt-out 的设备仍获得 `/sys/dev/<kind>/<major>:<minor>` 索引项，设备模型不创建也不在 `teardown` 时删除其节点。
- `kernel/core/comps/device/src/common/registration.rs`、`hooks.rs`：注册路径按 opt-out 标志跳过 devnode 请求；hooks 增加 ktest 用的 `pending_requests()` 检查口。
- `kernel/core/src/device/registry/block.rs`：新增 `SelfPublishingBlock`（`CREATES_DEVNODE = false` 的 BlockClass），块设备经 `register_model_device` 接入设备模型，注销走 `remove_wrapper_if_matches`。
- `kernel/core/comps/device/src/test/registration.rs`：新增注册/opt-out 行为的 ktest 用例。

### 验证

- core DM ioctl ktest 复跑 `81 passed; 0 failed; 159 filtered`。
- `--linear-integration` 完整套件五次真实运行全部 PASS：凌晨首轮 87s、legacy 对照 91s、结构化日志实验 A 88s、定稿 85s、新版 87s。LVM2 sysfs filter 不再拒绝块设备，guest 正常完成 PV/VG/LV 全流程。
- 内核改动未提交；`test/registration.rs` 新增用例未单独运行 ktest。

## 2. 结构化日志改造（dm-test 套件日志形态）

### 背景

套件旧日志为单一流文件，轮询 ready 时出现"41s/91s 超时"假象。排查确认全部是超时+1 秒被杀，真实 guest 12-13 秒 ready；并定位消费端规律：**FIFO 与 `tee` 之间不能加任何过滤器**——QEMU 对非 tty stdout 非阻塞写，`tr`/`sed -u` 等消费端会节流 chardev 写路径直到 guest console 卡死（实验矩阵：tee 直连 10s ready；tr 落文件、stdbuf tr、tr|tee、sed -u|tee 全部卡死）。此前"tee 缓冲"的判断是误诊：实际是 `tr` stdout 非终端时全缓冲。

### 改动（`myshell/lib/dm_nixos_test.sh`、`myshell/run_dm_system_tests.sh`）

- 一次运行一个日志目录 `${DM_TEST_LOG_ROOT}/${slug}/$(date +%Y-%m-%d-%H-%M)` + `latest` 符号链接；目录名取运行者本地时钟（容器已设 `TZ=Asia/Shanghai`）。
- 三文件产物：`console.log`（FIFO 经原生 `tee` 直写，保留原始字节序）、`summary.log`（host 里程碑与判定）、按 guest 分文件的 `qemu-stderr-*`；终端只输出带时间戳的里程碑/判定行。
- `dm_step`/`dm_emit` 判定行、入口脚本 PASS 行统一加 `\r\033[K` 行首保护：长命令折行回显与套件输出竞速会导致粘行（"11:21arget" 吃字符问题）。
- `dm_print_summary`/`dm_print_failure_context` 派生视图剥离 `\r`。
- `DM_STRUCT_LOG=0` 可整体回退 legacy 单流日志。

### 验证

见第 1 节五次 NixOS PASS（legacy 对照、实验 A、定稿、新版）；运行目录产物结构与 `latest` 链接按预期生成。

## 3. console 转义序列根因定性与 clean.log 完备剥离

### 背景

用户指出此前对 console 日志的转义处理是"治标不治本"，要求找到转义序列出现的根本原因；并指出 `cat` clean.log 仍会污染终端。

### 结论

- 根因：guest 的 systemd PID 1 按 UAPI Group 规范 15（OSC 3008 Hierarchical Context Signalling）在 `/dev/console` 无条件广播 boot 上下文记录及光标/调色板探测序列；规范未提供任何 opt-out（上游 issue systemd#41973 记录了同一问题）。原始字节流经检查完整无损，"转义失败"观感来自查看路径吞掉不可见 ESC 后露出的尾巴。
- 治本边界：guest 侧需修改镜像内 systemd（无开关，超出测试套件范畴，用户决定搁置 core.nix 的 `systemd.tty.term.*` 方案）；host 实时过滤不可行（FIFO 消费端只能接 `tee`，见第 2 节实验）。

### 改动

`myshell/lib/dm_nixos_test.sh` 的 `dm_close_log`：clean.log 剥离规则升级为字符级完备——先剥 OSC/DCS/PM/APC 字符串类序列，再剥 CSI、nF 序列与残余 ESC，最后删除除 `\n`、`\t` 外全部 C0/C1 控制字节。此前旧规则遗留 40 个 0x08（backspace）。

### 验证

对既有 `latest/console.log` 应用新规则：除 `\n`、`\t` 外零控制字符，行数与 CHECK_PASS 内容完好；重新生成的 clean.log 复验 CLEAN，可直接 `cat`。

## 5. C 回归 `REGRESSION_TESTS` 失效定位与接线恢复

### 现象

`AUTO_TEST=regression REGRESSION_TESTS=device/device_mapper make run_kernel` 报 `Regression test failed`。

### 根因（两层）

1. `REGRESSION_TESTS` 通道丢失：9 月 21 日提交 `962b76626` 曾同时接线 Makefile（变量定义 + `--init-args="/test/run_regression_test.sh $(REGRESSION_TESTS)"` 透传）与 selector 脚本；后续上游同步冲掉了 Makefile 侧两处改动，selector 脚本的过滤逻辑幸存。环境变量无法穿越 QEMU，guest 收到无参 runner，实际运行全量回归——该变量被静默忽略。
2. 全量回归的真正失败点为 `process/cgroup.sh` 2.2.4：busy 任务 2 秒墙钟仅记账约 0.6 秒 CPU（判据 ≥1.9 秒），两次实测 568ms/600ms 高度一致；host 空闲（load 0.18）、容器无 CPU 配额、KVM 已启用（`-accel kvm`、`-cpu host`），排除资源抢占，定性为本机环境限制。`device_mapper` C 回归在两次全量中均通过（qemu.log 证据），与 DM 无关。历史上 9 月 21/28 日的成功记录全部为 focused 运行，`process/cgroup` 此前从未在本机运行过。

### 改动

Makefile 恢复 `962b76626` 原样接线 4 行：`REGRESSION_TESTS ?=` 定义与 regression 分支 init-args 透传。无变量时仍为全量，行为向后兼容。用户决定不跑 upstream main 基线（接受为环境限制），DM 验证流程继续使用 focused。

### 验证

`AUTO_TEST=regression REGRESSION_TESTS=device/device_mapper make run_kernel`：182 passed、0 failed，`Test /test/device/device_mapper passed.`、`All regression tests passed.`、退出码 0；qemu.log 仅含 `Running test /test/device/device_mapper` 一个 selector，定向语义生效。
