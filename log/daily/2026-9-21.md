## Stage 5：收敛 V4 范围并补齐 DM 直接断言

- 按首轮审核修订 `log/device-mapper-optimization-v4.md`：拆分 VirtIO GET_ID 的 query/queue/设备不完成契约；区分既有 tracked lease 清理与新增生命周期缺口；补列 WAIT/`SA_RESTART`、真实 alias 恢复和 MlsDisk facade 边界。
- 用户决定将原 V4.5（CPUID/TSC）和 V4.6（test-kernel selector）移出 DM 验收方案：两项属于通用平台/测试基础设施，与 DM 功能无直接调用关系；本轮未为其补测试，也未修改启动配置或抽取生产接口。
- 新增/增强 Rust 直接断言：
  - inactive/active table 存活、替换与 clear 对真实 tracked backing 的保护和释放；
  - noflush 换表后旧 in-flight BIO 对旧 backing 的持有，最后 completion 后释放，新 backing 独立保护；
  - missing backing、容量、连续性三类 failed table-load 保持原非空 table identity、readonly、phase 与 lease，并释放临时 lease；
  - 有合法容量的实际 `DmDevice` 作为 linear/striped backing 均命中 `UnsupportedBackingDevice`；
  - 四个 block range wrapper 的 BIO 类型、sector range、空 segments、同步/异步完成、enqueue/completion 错误通道、batch 与 callback 恰一次。
- 新增 initramfs C 回归：
  - `DM_DEV_WAIT` 在 `SA_RESTART` handler 实际执行后不提前返回，rename 事件后原 ioctl 成功完成；保留无 `SA_RESTART` 返回 `EINTR` 的对照；
  - `BLKDISCARD`/`BLKZEROOUT` 在 8-sector zero target 上覆盖合法、未对齐、加法溢出、越界和合法/非法零长度 byte range。
- 本阶段主要补测试与 test-only fixture，未改变 table/BIO 生命周期、WAIT、range ioctl、DM-on-DM 拒绝等生产语义。
