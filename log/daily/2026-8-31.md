## 5. Flush 数据面覆盖收口 review

### 背景

准备继续数据面语义增强时，先核对当前技术文档和代码实现边界。`discard / write zeroes` 在技术文档中明确属于当前非目标，block `BioType` 当前也只有 Read / Write / Flush，因此本阶段不新增 guest discard/write-zeroes 脚本。

### 结论

现有 `aster-device-mapper` crate 已覆盖 flush 关键内核语义：

```text
linear table flush backing 去重。
striped table flush fan-out。
linear + striped mixed table shared backing 去重。
flush completion failure 返回 IoError。
backing enqueue flush 失败返回 IoError。
readonly mapper 允许 Read / Flush、拒绝 Write。
suspend 等待已提交 flush 完成，并拒绝 suspend 期间的新 flush。
```

本阶段没有新增代码和脚本；只更新滚动进度文档，把下一步从 discard/write-zeroes guest 假测收窄为现有慢系统回归或 queue limit / alignment / topology 审计。

### 测试

临时把根 `Cargo.toml` 的 `default-members` 收窄为 `kernel/core/comps/device-mapper` 后执行；验证完成后已恢复 `Cargo.toml`，并确认 `git diff -- Cargo.toml` 无输出。

## 6. 新增 Device Mapper error target

### 背景

本阶段从现有语义审计转向拓展 Asterinas 上的 DM target 功能。选择先实现边界清晰的 Linux DM `error` target：它不依赖 backing device，能为 guest 侧稳定 I/O error 场景提供基础。

### 改动

新增核心 target：

```text
kernel/core/comps/device-mapper/src/target/error.rs
```

更新核心 DM 数据面：

```text
kernel/core/comps/device-mapper/src/target/mod.rs
kernel/core/comps/device-mapper/src/table.rs
kernel/core/comps/device-mapper/src/lib.rs
```

实现语义：

```text
error target 无 backing 参数。
Read / Write 覆盖 error target 时完成为 BioStatus::IoError。
flush 对无 backing table 直接完成成功。
deps 为空。
纯 error table 的 max_nr_segments_per_bio 不因无 backing 变为 0。
跨 linear + error target 的 BIO 继续使用现有 split completion 聚合为 IoError。
```

更新 ioctl / dmsetup 控制面：

```text
kernel/core/src/device/misc/device_mapper.rs
```

覆盖：

```text

dmsetup create NAME --table "0 8 error" 成功。
dmsetup table/status 输出 error target。
```
