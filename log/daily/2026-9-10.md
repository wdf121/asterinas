# 2026-9-10 Device Mapper 进度

## 1. load 生命周期优化拆分提交

首次 table load 的 primary / alias 生命周期已提交为 `83b6187b3`（`拆分 Device Mapper load 的 primary 与 alias 生命周期`）。

- 首次成功 `DM_TABLE_LOAD` 在 table 完整构造、target 几何校验及 backing lease 获取后发布 `/dev/dm-N` primary node，再安装 inactive table。
- primary-only 状态下容量为 0、read 为 EOF、alias 不存在；首次 resume 用 `InitialResumeGuard` 激活 table 并发布 alias，失败恢复 inactive table 与 phase。
- primary-only rename/remove 已纳入 runtime 生命周期。

## 2. resume 换表屏障拆分提交

运行中 mapper 的直接 table replacement barrier 已提交为 `1815c7578`（`为 Device Mapper resume 建立换表屏障`）。

- `Running + active + inactive` 的普通 resume：切到 `Suspending`、等待已分配给 old table 的 BIO drain，再替换 active table。
- 该屏障期间新 BIO 现在进入 postponed 队列；replacement table 发布后按新 active table replay。

## 3. suspend / noflush 语义纠正

经 Linux UAPI 与本机 `dmsetup(8)` 核对，`DM_NOFLUSH_FLAG` 的语义是 suspend 时不 flush queued I/O，不是 resume 时直接切 active table。本阶段尚未提交。

### 实际改动

- `DmDeviceState` 增加 FIFO postponed BIO 队列。`Suspending` / `Suspended` 时，未映射的新 BIO 不再 `Refused`，而是成功接受并等待 resume。
- 普通 `suspend()` 保持 `Running -> Suspending -> drain in_flight -> Suspended`；`suspend_no_flush()` 直接进入 `Suspended`，不等待已经映射到 old table 的 BIO。
- `resume()` 成为唯一换表入口：安装 replacement active table 后，FIFO replay postponed BIO；no-flush suspend 的 old BIO 继续由 completion closure 持有 old table `Arc` 完成。
- 删除 `resume_no_flush()` 语义；control ioctl 仅在 `DM_SUSPEND_FLAG` 分支根据 `DM_NOFLUSH_FLAG` 选择 noflush suspend。`resume --noflush` 保持 CLI 兼容，但等价于普通 resume。
- `SubmittedBio` 新增仅供 deferred replay 使用的 drop-to-`IoError` 保护；replay mapping/backing enqueue 失败，或 remove 清理 postponed 队列时，调用方会收到 I/O error 而不会永久等待。

## 8. dmsetup 未支持命令边界

- `message`、`setgeometry` 和 `remove --deferred` 加入控制面 guest 的 expected-failure 断言：前两者被 decoder 以 `ENOTTY` 拒绝；deferred flag 以 `EOPNOTSUPP` 拒绝，失败后 mapper 仍可查询并由普通 remove 删除。
- `dmsetup` 当前不提供 arm-poll 子命令；core ktest 将 14（target message）、15（setgeometry）、16（arm-poll）三项 raw ioctl 统一锁定为 `ENOTTY`，并针对 `DM_DEV_REMOVE` 验证 deferred flag 的 `EOPNOTSUPP`。
- 本机 Linux 基线记录：linear target 的 message 返回 target-specific failure，setgeometry 成功；busy mapper 的 deferred remove 成功，关闭 FD 后设备消失。这些是 Asterinas 明确未支持的能力，不应误写成 Linux 的预期失败。
- 容器内两项定向 `aster-core` ktest 与控制面系统测试通过；guest shell-ready 10 秒、完整生命周期 34 秒，`SUMMARY_GAP_DM_CONTROL_PLANE: 0`、`TEST_PASS_DM_CONTROL_PLANE`。

## 10. P1.3 首次 resume 的失败原子性

- `InitialResumeGuard` 改为持有 `DmDeviceState` lock：首次 alias 发布期间 inactive table 与 phase 均不改变；alias 成功后才在同一临界区安装 active table、切换到 `Running` 并预留 postponed BIO replay，释放锁后才分派 BIO。
- alias publisher 新增注入 helper，ioctl ktest 可强制 publication failure；失败时 primary 保留、active 仍为空、同一 inactive table 保留，后续 resume 可重试。
- 容器内定向 ktest 通过：`initial_resume_guard_blocks_bios_until_commit`、`initial_resume_guard_drop_refuses_blocked_bios_without_dispatch`、两项 guard drop 状态保持、`initial_resume_guard_commit_keeps_active_table`，以及 `initial_alias_publication_failure_keeps_table_inactive`。
- `GUEST_READY_TIMEOUT=40 GUEST_QEMU_TIMEOUT=180 myshell/run_dm_system_tests.sh --control-plane` 通过：guest shell-ready 10 秒、完整生命周期 36 秒，`CHECK_PASS_DMSETUP_FIRST_LOAD_RESUME_LIFECYCLE`、`SUMMARY_GAP_DM_CONTROL_PLANE: 0`、`TEST_PASS_DM_CONTROL_PLANE`、`HOST_PASS_DM_CONTROL_PLANE`。`git diff --check` 通过；`cargo fmt --all --check` 仍仅报告 `table.rs` 三处既有格式差异。

## 11. P1.4 drain 期间的控制面并发

- 删除 ioctl 全程持有的 `DM_CONTROL_LOCK`。对已有 mapper 的 load、clear、suspend/resume、remove、rename 与首次 alias activation，统一以 `DmDevice` lifecycle guard 串行；取得 guard 后用 manager 中的同一 `Arc` 身份复核，避免旧 lookup 在并发 remove 后修改已脱离索引的 device。
- 普通 suspend 和 running replacement resume 仍先把 phase 切为 `Suspending` 再等待 old BIO drain；区别是等待期间不再阻塞其他 mapper 的 status、table 查询或 create。相同 mapper 的 clear 只能在 drain 完成并释放 lifecycle guard 后执行。
