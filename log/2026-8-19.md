# 2026-8-19 Device Mapper 工程改动日志

本文按小阶段记录今天实际发生的工程改动。单纯文档解释、代码复核、后续规划不写入本日志；测试和验证结果跟随对应小阶段记录。

## 1. suspend 状态机边界修正

涉及文件：

- `kernel/comps/device-mapper/src/device.rs`

### 原来

fresh DM device 还没有 active table 时执行 suspend，也会递增 `event_nr`。

例子：

```text
DM_DEV_CREATE
DM_DEV_SUSPEND with suspend flag
DM_DEV_STATUS
```

原来可能看到 `event_nr` 从 0 变成 1，即使这个 device 还没有真正 active table，也没有实际 I/O 屏障变化。

### 现在

只有存在 active table 时，`suspend()` 才递增 `event_nr`。

同时，`Suspending` 阶段对外 status 也表现为 suspended，避免 control 面在等待 in-flight I/O drain 时仍显示 running。

### 测试

已有/补充 ktest 锁住 fresh device suspend 不错误增加 `event_nr`，以及 suspend/drain 期间 status 表现为 suspended。

## 2. flush 转发模型改成异步 fan-out

涉及文件：

- `kernel/comps/device-mapper/src/table.rs`

### 原来

DM table 收到 Flush BIO 后，会遍历 backing device，并在 enqueue 路径里同步调用 `submit_and_wait()`。

```text
上层 flush -> DM -> backing A flush submit_and_wait -> backing B flush submit_and_wait
```

如果底层 flush 被延迟完成，DM enqueue 路径会同步卡住；在 suspend/drain 场景里容易造成不该有的阻塞。

### 现在

Flush BIO 改成：

```text
上层 flush
  -> DM 按 backing device 去重
  -> 给每个 backing 异步提交一个 Flush BIO
  -> FlushCompletion 聚合所有 child flush 完成结果
  -> 全部成功则原 flush 成功；任意失败则原 flush 失败
```

一个 LV 跨两块盘时，原来是先等第一块盘 flush 完再等第二块盘；现在两个 backing flush 都异步提交，最终聚合完成。

### 测试

补充 ktest 锁住：

- flush 每个 backing 只转发一次；
- flush child completion 失败会传播到原始 BIO；
- backing enqueue flush 失败时，原始 flush BIO 以 `IoError` 完成。

## 3. BIO / table / ioctl 边界测试补强

涉及文件：

- `kernel/comps/block/src/bio.rs`
- `kernel/comps/device-mapper/src/table.rs`
- `kernel/src/device/misc/device_mapper.rs`

### 内容

补充 ktest 锁住多个边界：

- child BIO 可以跨原始 segment 边界；
- 跨 linear target 的 BIO split 后，各 child range 正确 remap；
- BIO 越过 table 范围时拒绝；
- mapper capacity 来自 table length；
- queue limit 当前取所有 backing 的最小 `max_nr_segments_per_bio`；
- table status 多 target 的 Linux-style `next` offset；
- table deps backing device 去重；
- table status/deps buffer-full 语义；
- resume 激活 inactive table；
- running 状态下 reload + resume 替换 active table；
- multi-target table load 使用 `dm_target_spec.next` 正确解析。

## 4. 对齐 Linux linear status 输出

涉及文件：

- `kernel/src/device/misc/device_mapper.rs`

### 原来

需要确认 Asterinas 的 `DM_TABLE_STATUS` 对 linear target 输出是否和 Linux `dm-linear` 一致。

### 现在

确认并锁住两种输出：

1. 不带 `DM_STATUS_TABLE_FLAG`：对齐 Linux `STATUSTYPE_INFO`，linear 参数为空；
2. 带 `DM_STATUS_TABLE_FLAG`：对齐 Linux `STATUSTYPE_TABLE`，linear 参数为：

```text
<major>:<minor> <backing_start>
```

### 例子

如果 table 是：

```text
0 4096 linear 8:1 2048
```

那么 table status 输出参数是：

```text
8:1 2048
```

info status 输出参数是空字符串。

### 测试

补 ktest 锁住 info/table 两种 status 输出差异。

## 5. 收紧 linear 参数解析格式

涉及文件：

- `kernel/src/device/misc/device_mapper.rs`

### 原来

`parse_linear_params()` 接受标准两字段：

```text
8:1 2048
```

也额外接受：

```text
8:1 2048 sectors
```

也就是把第三个字段 `sectors` 当成可选单位后缀。

### 现在

只接受严格两字段：

```text
<major>:<minor> <backing_start>
```

例如：

```text
8:1 2048
```

这些都会被拒绝：

```text
8:1
8:1 x
8:1 2048 sectors
8:1 2048 extra
bad 2048
8:1 -1
65536:1 0
8:4294967296 0
```

如果用户态传：

```text
0 4096 linear 8:1 2048 sectors
```

原来可能加载成功，生成 inactive table；现在 `DM_TABLE_LOAD` 返回 `EINVAL`，并且 device state 不变。

### 测试

补充 ktest 覆盖：

- 合法参数；
- 缺字段；
- 额外字段；
- 畸形 `major:minor`；
- major/minor/start 数值溢出；
- table load 失败不改变 device state。

## 6. 钉住 rename 失败回滚语义

涉及文件：

- `kernel/src/device/misc/device_mapper.rs`

### 原来

`device_rename()` 里已经有失败回滚逻辑：

```text
先把 manager 名字 old -> new
再 rename /dev/mapper alias
如果 alias rename 失败，再把 manager 名字 new -> old
```

但这段逻辑直接绑在真实 `rename_block_mapper()` 上，不方便用 ktest 模拟 alias rename 失败。

### 现在

把 runtime rename 流程抽成：

```text
rename_device_runtime(manager, device, new_name, rename_alias)
```

生产路径仍传入真实 `rename_block_mapper()`，行为不变；测试路径可以传入故意失败的 `rename_alias`，模拟 `/dev/mapper/<new>` 已存在或 alias rename 失败。

### 例子

已有设备：

```text
manager name = dm-rollback-old
uuid = dm-rollback-uuid
inactive table 已加载
```

执行 rename 到：

```text
dm-rollback-new
```

如果 alias rename 返回 `EEXIST`，现在 ktest 锁住结果：

```text
返回 EEXIST
manager 仍能通过 dm-rollback-old 查到设备
manager 不能通过 dm-rollback-new 查到设备
uuid 仍指向原设备
设备内部 name 回到 dm-rollback-old
device status 不变
```

### 测试

补充 ktest 覆盖：

- rename 成功时 manager/name/uuid 一起更新；
- rename 到同名是 no-op，不调用 alias rename；
- alias rename 失败时 manager 和设备内部 name 回滚，status 不变。

## 7. 钉住 active/inactive query flags 语义

涉及文件：

- `kernel/src/device/misc/device_mapper.rs`

### 原来

`DM_DEV_STATUS` 的 target count 选择逻辑直接写在 `device_status()` 中，需要通过全局 manager lookup 路径才能测试。

### 现在

抽出：

```text
device_status_for_device(buffer, device)
```

生产路径仍然通过 `lookup_device()` 找到设备后调用该 helper，行为不变；测试可以直接构造本地 `DmManager` 和 `DmDevice`，验证 `DM_QUERY_INACTIVE_TABLE_FLAG` 对 `DM_DEV_STATUS` 的影响。

### 例子

```text
active table:   0 4 linear 1:1 100
inactive table: 0 4 linear 1:2 200
                4 8 linear 1:3 300
```

不带 flag：

```text
DM_DEV_STATUS target_count = 1
DM_TABLE_STATUS 输出 1:1 100
DM_TABLE_DEPS 输出 1:1
```

带 `DM_QUERY_INACTIVE_TABLE_FLAG`：

```text
DM_DEV_STATUS target_count = 2
DM_TABLE_STATUS 输出 1:2 200 和 1:3 300
DM_TABLE_DEPS 输出 1:2 和 1:3
```

### 测试

补充 ktest 覆盖：

- active table 和 inactive table 同时存在时，不带 flag 查询 active；
- 带 `DM_QUERY_INACTIVE_TABLE_FLAG` 查询 inactive；
- `DM_DEV_STATUS` 的 target count 按 selected table 返回；
- `DM_TABLE_STATUS` 按 selected table 输出 target records；
- `DM_TABLE_DEPS` 按 selected table 输出 backing deps；
- active/inactive 不串表。

## 8. 补齐 DM_DEV_WAIT 最小 event 语义

涉及文件：

- `kernel/comps/device-mapper/src/device.rs`
- `kernel/src/device/misc/device_mapper.rs`

### 原来

`event_nr` 已经会随 table load、resume、suspend 等状态变化递增，并通过 status header 返回，但 ioctl 命令表没有接入 Linux ABI 的 `DM_DEV_WAIT_CMD = 8`。

用户态如果用 wait/event 模型等待 mapper 状态变化，8 号 ioctl 会被当成未支持命令返回 `ENOTTY`。

### 现在

`DmDevice` 增加 event wait queue。`load_table()`、`clear_inactive_table()`、`suspend()`、`resume()` 和 remove 成功路径在 `event_nr` 真实变化后唤醒等待者。

控制面新增 `DM_DEV_WAIT` 最小语义：

```text
输入 event_nr != 当前 event_nr：立即返回当前 header
输入 event_nr == 当前 event_nr：等待下一次 event_nr 变化后返回
```

`DM_DEV_WAIT` 等待期间不持有全局 control lock，避免 wait 阻塞后续能改变 `event_nr` 的 ioctl。

### 测试

补充 ktest 覆盖：

- event 已变化时 `wait_event()` 立即返回；
- event 未变化时 `wait_event()` 阻塞到状态变化后返回；
- `DM_DEV_WAIT` helper 返回更新后的 event header；
- ioctl 解码接受 `DM_DEV_WAIT_CMD = 8`。

## 9. 收口 DM ioctl flags 兼容边界

涉及文件：

- `kernel/src/device/misc/device_mapper.rs`

### 原来

控制面只显式处理少数 flag，例如：

```text
DM_PERSISTENT_DEV_FLAG
DM_STATUS_TABLE_FLAG
DM_QUERY_INACTIVE_TABLE_FLAG
DM_UUID_FLAG
DM_SUSPEND_FLAG
```

其它 Linux DM flag 如果从用户态传入，很多会被自然忽略。这样对无害兼容 flag 可以工作，但对只读、deferred remove、IMA measurement 或未知高位 flag 来说，容易形成“用户态以为支持，内核实际没做到”的错误兼容。

### 现在

补齐 Linux 6.6 `dm-ioctl.h` 中 0..19 位的 flag 常量，并新增统一输入校验：

```text
未知 flag 位 -> EINVAL
当前不能安全支持的语义 -> EOPNOTSUPP
无害兼容 flag -> 显式允许并忽略
命令专用 flag -> 只在有真实输入语义的 ioctl 中生效；其它命令上的陈旧兼容位按需忽略
```

当前显式拒绝：

```text
DM_READONLY_FLAG
DM_DEFERRED_REMOVE
DM_IMA_MEASUREMENT_FLAG
```

当前显式允许并忽略：

```text
DM_SKIP_BDGET_FLAG
DM_SKIP_LOCKFS_FLAG
DM_NOFLUSH_FLAG
```

`DM_SECURE_DATA_FLAG` 被允许，ioctl 结束后会清零内核临时 buffer。

### 测试

补充 ktest 覆盖：

- 无害兼容 flag 可通过校验；
- output-only 旧 flag 不影响最终状态；
- 未知高位 flag 返回 `EINVAL`；
- 只读、deferred remove、IMA measurement 返回 `EOPNOTSUPP`；
- persistent/status-table/query-inactive/uuid 等命令专用 flag 只能用于对应 ioctl；
- 关键 Linux flag 位号保持不变。

## 10. 重构 DM 系统测试脚本体系

涉及文件：

- `myshell/lib/dm_nixos_test.sh`
- `myshell/run_cross_target_bio_regression.sh`
- `myshell/run_cross_pv_large_write_test.sh`
- `myshell/run_lvm2_resize_test.sh`
- `myshell/run_dm_control_abi_test.sh`
- `myshell/run_dm_system_tests.sh`

### 原来

三个系统级脚本分别维护 guest 启动、QEMU 占用检查、测试盘重置、root shell 等待、FIFO 注入、summary 和失败上下文输出逻辑。

它们能验证真实 LVM2/DM 路径，但脚本结构是按历史阶段逐步补出来的，公共 host-side 逻辑重复，后续继续加 control ABI 或组合测试时容易复制问题。

### 现在

新增公共库：

```text
myshell/lib/dm_nixos_test.sh
```

统一承载：

```text
QEMU 占用检查
NixOS 镜像检查
测试盘重置
guest shell 等待
FIFO 注入 guest script
summary 输出
失败上下文输出
单 guest / 双 guest 测试编排
```

原三个脚本改为复用公共库，并保持原有测试流程和 `HOST_PASS_*` 标记不变。

新增轻量 control ABI smoke：

```text
myshell/run_dm_control_abi_test.sh
```

用于通过真实 dmsetup 路径覆盖 `/dev/mapper/control`、target version、create/table/status/deps/info、`DM_DEV_WAIT` stale event 和 `--noflush` suspend/resume。

新增组合入口：

```text
myshell/run_dm_system_tests.sh --quick
myshell/run_dm_system_tests.sh --data
myshell/run_dm_system_tests.sh --lvm2
myshell/run_dm_system_tests.sh --full
```

后续可以按改动范围选择系统测试，而不是固定跑三套历史脚本。

### 测试

已执行 shell 语法检查：

```text
bash -n myshell/lib/dm_nixos_test.sh \
       myshell/run_cross_target_bio_regression.sh \
       myshell/run_cross_pv_large_write_test.sh \
       myshell/run_lvm2_resize_test.sh \
       myshell/run_dm_control_abi_test.sh \
       myshell/run_dm_system_tests.sh
```

首次 `--quick` 运行暴露两个问题：

- 公共 runner 用未锚定 grep 匹配 `TEST_PASS_*`，会被 guest 输入回显里的 `echo TEST_PASS_*` 误导；已改为只接受行首真实 marker，并检查 `TEST_FAIL_*` / `HOST_FAIL_*`；
- `dmsetup create` 的 `DM_TABLE_LOAD` 会携带 `DM_PERSISTENT_DEV_FLAG` 陈旧位，原 flags 校验过严；已修正为 create 时使用该 flag，其它 ioctl 中兼容忽略。

修正后已重新执行：

```text
cargo fmt --all
cargo fmt --all --check
timeout 1200 cargo osdk test device_mapper
make nixos
myshell/run_dm_system_tests.sh --quick
```

结果：通过，`--quick` 输出：

```text
CHECK_PASS_DM_VERSION_AND_TARGETS
CHECK_PASS_DM_STATUS_DEPS_INFO
CHECK_PASS_DM_WAIT_AND_NOFLUSH
TEST_PASS_DM_CONTROL_ABI
CHECK_PASS_MAPPER_READBACK_MD5
CHECK_PASS_BACKING_SPLIT_MD5
TEST_PASS_CROSS_TARGET_BIO
```
