本文按小阶段记录今天实际发生的工程改动。单纯文档解释、代码复核、后续规划不写入本日志；测试和验证结果跟随对应小阶段记录。

## 1. DmTable target enum 化

涉及文件：

- `kernel/comps/device-mapper/src/target/mod.rs`
- `kernel/comps/device-mapper/src/table.rs`
- `kernel/src/device/misc/device_mapper.rs`
- `docs/device-mapper-technical-maintenance.md`

### 原来

`DmTable` 内部直接保存：

```text
Vec<LinearTarget>
```

这对当前 linear-only 主路径足够，但后续引入 striped target 时，table/status/deps/BIO split 都会继续被 `linears()` API 绑定住。

### 现在

新增最小 target enum：

```text
DmTarget::Linear(LinearTarget)
```

`DmTable` 内部改为保存 enum-based target list：

```text
Vec<DmTarget>
```

保留当前唯一公开构造入口：

```text
DmTable::new_linear(Vec<LinearTarget>)
```

该入口内部把 linear target wrap 成 `DmTarget::Linear`，再复用统一 table 校验：

```text
非空
从 logical sector 0 开始
target 连续无空洞/重叠
不允许 DM-on-DM backing
```

数据面路径同步改为按 `DmTarget` 迭代：

```text
metadata queue limit 汇总
backing deps 去重
BIO part 查找
single BIO remap
dynamic split 后 child remap/enqueue
flush backing 去重 fan-out
```

control status 路径改为遍历 `table.targets()` 并匹配 `DmTarget::Linear` 输出原来的 linear status record。`DM_TABLE_LOAD` 仍只解析 `linear`，继续拒绝 `striped`/unknown target。

本阶段没有实现 striped parser、striped mapping、target trait 或 target registry。

### 测试

补充 table 层 ktest，确认 `DmTable::new_linear` 会按顺序保存为 `DmTarget::Linear`，且 target count、logical range、backing id 不变。

执行：

```text
cargo fmt --all --check
timeout 1200 cargo osdk test device_mapper
```

结果：通过。ktest 期间临时将根 `Cargo.toml default-members` 缩小到只跑 `kernel`，验证结束后已恢复，并确认 `git diff -- Cargo.toml` 无输出。

## 2. 新增 striped 参数解析与静态校验 helper

涉及文件：

- `kernel/comps/device-mapper/src/lib.rs`
- `kernel/comps/device-mapper/src/target/mod.rs`
- `kernel/comps/device-mapper/src/target/striped.rs`
- `docs/device-mapper-technical-maintenance.md`

### 原来

`TARGET_VERSIONS` 已经声明 `striped` 用于 LVM2 预检兼容，但代码中没有 striped 参数 parser，也没有 stripe/chunk 容量公式测试。

真实 `DM_TABLE_LOAD` 遇到 striped 仍返回 `EINVAL`，不安装 table。

### 现在

新增 `target/striped.rs`，只实现 parser 和静态校验 helper，不接入 table load 或数据面。

支持解析格式：

```text
<stripe_count> <chunk_size> <dev1> <offset1> <dev2> <offset2> ...
```

新增 `StripedTargetParams`，保存：

```text
stripe_count
chunk_size
每个 stripe 的 DeviceId 和 backing_start
```

新增 required sectors 公式，按 stripe index 计算给定 logical length 下该 backing 实际需要多少 sectors。例如：

```text
N=2, C=128, L=300 -> stripe0=172, stripe1=128
N=3, C=64,  L=400 -> stripe0=144, stripe1=128, stripe2=128
```

静态校验覆盖：

```text
zero length
logical range overflow
stripe width overflow
backing_start + required overflow
backing range out of bounds
capacity 数量和 stripe 数量不一致
```

新增 `TableError::InvalidTargetParams` 表示 target 参数格式或几何信息无效。

本阶段仍不新增 `DmTarget::Striped`，`DM_TABLE_LOAD` 仍拒绝 striped。

### 测试

新增 ktest 覆盖：

```text

mixed whitespace
缺字段/多字段
zero stripe count
zero chunk size
invalid major:minor
invalid backing start
required sectors uneven tail 公式
backing capacity exact-fit / out-of-bounds
logical overflow / backing overflow
```

执行：

```text

timeout 1200 cargo osdk test device_mapper
```

结果：通过。第一次直接使用全量 default-members 跑 ktest 时因为 unrelated crate 并发和后续编译修正中断；最终临时将根 `Cargo.toml default-members` 缩小到只跑 `kernel` 后通过。验证结束后已恢复 `Cargo.toml`，并确认 `git diff -- Cargo.toml` 无输出。

## 3. 新增 StripedTarget sector mapping helper

涉及文件：

- `kernel/comps/device-mapper/src/target/striped.rs`
- `docs/device-mapper-technical-maintenance.md`

### 原来

上一阶段已有 `StripedTargetParams`，能解析 striped 参数并校验每个 stripe 需要的 backing sectors，但还没有 runtime target，也没有 logical sector 到 stripe/backing sector 的映射 API。

### 现在

新增 runtime helper：

```text
StripedTarget
StripedTargetStripe
StripedSectorMap
```

`StripedTarget::new()` 接收：

```text
logical_start
length
StripedTargetParams
Vec<BlockDeviceLease>
```

构造时校验：

```text
length 非 0
logical range 不溢出
backing lease 数量等于 stripe count
backing lease id 和 params 中的 DeviceId 一致
backing capacity 满足 required sectors 公式
stripe width 计算不溢出
```

新增 `map_sector(logical)`，按以下公式返回 stripe index、backing id、backing sector：

```text
offset = logical - logical_start
row = offset / stripe_width
within_row = offset % stripe_width
stripe_index = within_row / chunk_size
chunk_offset = within_row % chunk_size
backing_offset = row * chunk_size + chunk_offset
backing_sector = backing_start[stripe_index] + backing_offset
```

本阶段仍不新增 `DmTarget::Striped`，不修改 `DmTable`、`DM_TABLE_LOAD`、status/deps 或 BIO split/remap。

### 测试

新增 ktest 覆盖：

```text
StripedTarget 构造 happy path 和 exact-fit capacity
length 0
logical overflow
backing capacity 不足
backing start overflow
backing 数量不匹配
backing id 不匹配
2 stripe / chunk 4 / logical start 10 的边界映射
3 stripe / chunk 3 / partial final row 的映射
```

执行：

```text

timeout 1200 cargo osdk test device_mapper
```

结果：通过。ktest 期间临时将根 `Cargo.toml default-members` 缩小到只跑 `kernel`，验证结束后已恢复，并确认 `git diff -- Cargo.toml` 无输出。

## 4. 新增 StripedTarget range split helper

涉及文件：

- `kernel/comps/device-mapper/src/target/striped.rs`
- `docs/device-mapper-technical-maintenance.md`

### 原来

`StripedTarget::map_sector()` 已经能映射单个 logical sector，但后续 BIO split 需要处理 logical range。跨 chunk 的 range 不能只按起点 remap，否则会把跨 stripe 的 I/O 错误落到同一个 backing。

### 现在

新增 `StripedRangeMap`：

```text
logical_range
stripe_index
backing_id
backing_range
```

新增 `StripedTarget::map_range()`，把一个完全位于 target 内的 logical range 按 striped chunk 边界拆分。

例如 2 stripe、chunk size 4、logical start 10 时：

```text
12..14 -> stripe0 backing 102..104
14..18 -> stripe1 backing 200..204
18..22 -> stripe0 backing 104..108
22..23 -> stripe1 backing 204..205
```

该 helper 只生成映射描述，不提交 BIO，不调用 `SubmittedBio::split()`，也不接入 `DmTable`。

### 测试

新增 ktest 覆盖：

```text

跨多个 chunk/stripe 的 range
range end 等于 target end
空 range / target 前 / target 后 / 部分越界 / start > end
每个 range part 与 map_sector(part.start) 保持一致
```

## 5. 为 striped 接入准备多 backing target 抽象

涉及文件：

- `kernel/comps/device-mapper/src/target/mod.rs`
- `kernel/comps/device-mapper/src/target/striped.rs`
- `kernel/comps/device-mapper/src/table.rs`
- `docs/device-mapper-technical-maintenance.md`

### 原来

`DmTable` 的内部汇总路径仍围绕 single-backing target 接口写：

```text
target.backing_id()
target.backing()
```

这对 linear target 足够，但 striped target 一个 target 内会持有多个 backing。后续如果直接加 `DmTarget::Striped`，table deps、flush、queue limit 和 DM-on-DM backing 检查都会先遇到单 backing 假设。

### 现在

`DmTarget` 新增多 backing 遍历 helper：

```text
for_each_backing_id()
for_each_backing()
```

当前 `DmTarget` 仍只有 `Linear` variant，因此 linear 行为不变；但 `DmTable` 的汇总逻辑已经改为通过 plural helper 遍历 backing：

```text
metadata queue limit：遍历所有 target 的所有 backing 后取最小值
backing_ids：遍历所有 backing id 并按首次出现顺序去重
enqueue_flush：遍历所有 backing，按 DeviceId 去重后 fan-out
new_targets：遍历所有 backing，继续拒绝 DM-on-DM backing
```

`StripedTarget` 同步提供同形 backing 遍历 helper，后续把它包进 target enum 时可以直接接到 `DmTarget` plural helper。

本阶段仍不新增可加载的 `DmTarget::Striped`，不修改 `DM_TABLE_LOAD`，不修改 table status/deps 输出格式，也不接入 BIO striped 数据面。

### 测试

补充/调整 ktest 覆盖：

```text
DmTarget linear variant 的 for_each_backing_id / for_each_backing 返回唯一 backing
DmTable metadata 从所有 backing 的 queue limit 中取最小值
StripedTarget for_each_backing_id / for_each_backing 能遍历 target 内所有 stripe backing
```

## 7. 接入 striped table load/status/deps 控制面

涉及文件：

- `kernel/comps/device-mapper/src/target/mod.rs`
- `kernel/comps/device-mapper/src/target/striped.rs`
- `kernel/comps/device-mapper/src/table.rs`
- `kernel/src/device/misc/device_mapper.rs`
- `docs/device-mapper-technical-maintenance.md`

### 原来

`striped` 已有参数解析、静态校验、sector mapping、range split 和多 backing helper，但还不能作为 `DmTarget` variant 进入 table。

`DM_TABLE_LOAD` 仍只接受 `linear`，`DM_TABLE_STATUS` 也只会输出 linear target record。`DM_TABLE_DEPS` 虽然已经通过 `table.backing_ids()` 汇总 backing，但没有 striped target 可供验证。

### 现在

`DmTarget` 新增：

```text
DmTarget::Striped(StripedTarget)
```

`DmTarget` 的 logical range、length、backing 遍历 helper 已支持 linear 和 striped。single-backing helper 改为只对 linear 返回有效值，避免把 striped 误当成“第一个 backing”的 linear target。

`DmTable::new_targets()` 公开为通用构造入口，继续复用原来的 table 非空、从 0 开始、target 连续、DM-on-DM backing 拒绝和 queue limit/deps 汇总逻辑。含 striped target 的 table 当前会显式拒绝 BIO，避免在 read/write split/remap 尚未接入时形成半成品数据面。

`DM_TABLE_LOAD` 现在支持：

```text
linear
striped
```

其中 striped 分支复用 `StripedTargetParams::parse()` 和 `StripedTarget::new()`，按参数中的 stripe 顺序查找 backing lease。所有 target 都解析和构造成功后才替换 inactive table；参数错误、缺 backing 或 range/capacity 错误仍保持失败不改设备状态。

`DM_TABLE_STATUS | DM_STATUS_TABLE_FLAG` 会对 striped 输出 canonical 参数：

```text
<stripe_count> <chunk_size> <dev1> <offset1> <dev2> <offset2> ...
```

`DM_TABLE_STATUS` info 模式仍输出空 params。`DM_TABLE_DEPS` 不新增 striped 特判，继续通过 `table.backing_ids()` 返回所有 backing 并按首次出现顺序去重。

本阶段仍不接入 striped BIO chunk split/remap，不新增 `myshell/dm_striped/` 系统脚本，也不宣称 LVM2 striped 路径可用。

### 测试

补充 ktest 覆盖：

```text

StripedTarget for_each_stripe status 元数据遍历
DmTable::new_targets 接受 striped 和 linear+striped 连续 table
含 striped table 的 read/write/flush BIO 返回 Refused
DM_TABLE_LOAD 成功加载 striped 和 linear+striped 混合 table
invalid striped params、missing backing、range/capacity 错误失败不改状态
DM_TABLE_STATUS 输出 striped canonical params 和 info empty params
DM_TABLE_STATUS 对 striped 长 params 的 buffer-full 语义
DM_TABLE_DEPS 返回 mixed linear/striped backing 并去重
unknown target 仍拒绝，striped 不再作为 unsupported target
```
